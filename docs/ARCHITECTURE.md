# Hyperday — Architecture

## Targets

| Target | Contains | Notes |
|---|---|---|
| `DayLive` (app) | `App/` + `Shared/` | SwiftUI app, stores, intents, Live Activity control |
| `DayLiveWidget` (extension) | `Widget/` + 3 files from `Shared/` | Renders the Live Activity only. Compiled with `WIDGET_EXTENSION` |

The project is generated by **XcodeGen** from `project.yml`. Don't edit the `.xcodeproj`.

## Data flow

```
EventKit ──┐
           ├─► DayEngine.snapshot(blocks, overrides, steps, now) ─► DaySnapshot
BlockStore ┘                                                       │
                                                                   ├─► contentState() ─► ActivityKit ─► Lock Screen / Island
CategoryStore ── display color / category ─────────────────────────┤
                                                                   └─► HistoryStore.recordToday() ─► Stats
```

- **`DayEngine`**: pure functions with no iOS APIs. Rules:
  - Overlaps: the block that started first becomes the title; the other becomes "also:".
  - Bar segments come from non-overlapping blocks. If the current block has steps, the bar shows the steps instead.
  - The action is **Step n/N** while steps remain, then **Done**. In a gap it's **Start next**.
- **`LiveActivityManager`** (main actor):
  - Merges overlapping refreshes into one.
  - Auto-starts the activity only when something is left today; **Go Live** always starts it.
  - Ends the activity when the day is over.
  - Restarts it after 7.5 hours, but only while the app is in the foreground.
  - Schedules a best-effort background refresh at the next block boundary.
- **Intents**:
  - `BlockActionIntent` (Step / Done / Start next) is a `LiveActivityIntent`, so it runs in the **app process**. That's why no App Group is needed.
  - `AddBlockIntent` powers Siri and Shortcuts.
- **Stores**: `BlockStore`, `CategoryStore` and `HistoryStore` are `ObservableObject` singletons that save JSON to Documents on every change.

## Color resolution

```
manual category override  >  calendar color (Settings › Calendars; "Tesla" defaults to #E31937)  >  category from rules  >  fallback
```
Stats always use the **category**, never the calendar color, so the numbers stay meaningful.

## UI system

- **Theme tokens** live in `Components.swift` as dynamic light/dark colors:
  - bg #FFF/#111112 · section #F4F4F4/#18181A · card #FFF/#1E1E20
  - border #E0E0E0/#2E2E31 · text #171A20/#F4F4F4 · muted #5C5E62/#A2A3A5
  - blue #3E6AE1 · red #E31937
- **Components**: `HeaderBar`, `Caps`, `InfoRow`, `PrimaryButtonStyle` / `SecondaryButtonStyle`, `cardBox()`, `Chip`, `FlowLayout`, `PillNav`, `BlockRow`, `CategoryChips`.
- **Tab bar**: the native `TabView`. It becomes Liquid Glass on iOS 26+ and minimizes when you scroll down.

## Constraints to keep in mind

- `ContentState` must stay small (ActivityKit's limit is 4 KB) and must decode older payloads. New fields should be optionals.
- The widget can't read the app's files, so everything it shows must travel in `ContentState`.
- Lock Screen card height is about 160pt. Check new lines against that budget.
